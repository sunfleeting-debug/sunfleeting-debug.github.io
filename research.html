研究方向 ​

代码生成Code Generation

从自然语言描述或代码上下文出发，让模型直接产出可运行的代码。这条线已经从函数级补全走到仓库级、多文件级的生成，评价方式也从文本相似度转向基于执行的测试（HumanEval、MBPP、BigCodeBench）。

关注：指令微调与反馈驱动的强化学习 · 仓库级与长上下文建模 · 生成结果的正确性评测
代码编辑Code Editing

与「从零生成」相对：在既有代码上做可控的最小改动——修缺陷、重构、补全、响应审查意见。它比生成更苛刻的地方在于，改动必须嵌回原有结构而不破坏语法，而且改动本身要能被解释。

关注：基于 AST / 树的编辑表示 · 编辑序列的学习与检索复用 · 上下文感知的代码填充（infilling） · 编辑质量与可编译性
量子软件工程Quantum Software Engineering

把软件工程里成熟的那套方法搬到量子程序上：量子线路的测试与调试、量子-经典混合程序的分析与验证，以及用大模型辅助量子代码的生成与纠错。

关注：量子程序的测试用例生成 · 量子-经典混合工作流建模 · 大模型在量子代码上的能力边界（起步阶段）

科研项目 ​

HIsCCS —— 基于历史检索增强的大语言模型提交消息生成

2026.05 – 2026.09论文投稿中VS Code / JetBrains 双平台插件
问题
既有自动提交消息生成方法内容单调、语义相关性不足，且难以适应不同开发者的编写风格。
做法
把开发者自己的历史提交当作个性化上下文，设计并实现 HIsCCS：先用稀疏与稠密两种检索筛出与当前代码变更最相关的历史提交，再做检索增强生成。
我的工作
负责检索增强生成流程的整体设计，把系统拆成检索、提示增强、消息生成三段。检索侧用 TF-IDF / BM25 做稀疏检索，用 CodeT5 嵌入向量加余弦相似度做稠密检索，取 Top-k 条历史提交及其消息；提示侧设计包含任务指令、代码变更、历史上下文、用户输入前缀与输出约束的 Prompt 模板，并控制历史信息规模，避免无关上下文干扰生成；生成侧打通 Llama-3-8B、GPT-3.5-Turbo、DeepSeek 的 API 调用与本地推理。此外实现 VS Code 插件的核心交互（代码差异获取、Git 历史读取、提交消息的推荐与补全两种模式），并参与 JetBrains 插件适配与双平台联调。
实验结果
在 multilingual CMG 数据集上，对比 CodeT5、CodeReviewer、RACE、GPT-3.5-Turbo、Llama-3-8B 及其历史信息增强版本。HIsCCS 在 BLEU、METEOR、Log-MNEXT 三项指标上均优于「使用全部历史信息」的基线方法，相对提升约 40% / 32% / 23%；人工评价与 Wilcoxon 符号秩检验进一步验证了方法的有效性与统计显著性。

基于认知锚点与知识追踪的个性化学习者建模研究

2025.07 – 2026.06国家发明专利 202610780069.3（实审中）指导教师 段桂华
问题
大模型驱动的个性化学习中，学习者画像构建粗糙、知识掌握状态难以动态追踪、学习效果评测缺乏细粒度量化指标。
做法
围绕认知锚点知识体系，构建面向学习者画像与知识追踪的动态建模系统：以细粒度知识点为基本单元，建立融合多源行为数据的学习者状态表征，支撑个性化内容生成、教学决策与效果评测。
我的工作
依托课标学科知识体系与课程教学逻辑，把传统粗粒度知识点做细粒度梳理与层级拆分，搭建适配智能诊断场景的认知锚点知识图谱；基于 LLM Embedding 完成试题文本与学习者行为的向量化，结合语义相似度与置信度阈值，建立「试题—知识点—学习者状态」的双向映射机制；挖掘试题的推理逻辑与结构特征，构建可计算的语义难度指标与知识掌握置信度动态评估体系；基于学生作答数据构建认知状态向量，通过掌握度偏差分析定位薄弱锚点，生成个性化学习目标向量与内容推荐策略。
成果
参与国家发明专利并进入实审阶段，完整打通专利算法闭环，完成后端服务与原型系统落地。认知状态评估模型支持学习者画像的细粒度刻画与知识追踪的动态推断；生成的个性化学习目标向量与内容推荐策略已在校园教学试点中验证。

论文阅读 ​

以下是精读过的论文，按主题分组，点标题可到原文（DOI）。阅读方式是先把原文过一遍，再逐节整理成中文精读稿（结构、图表、实验设置都对着原文核过），留下来当后续工作的索引。

代码生成

A Survey on Large Language Models for Code Generation
Jiang 等 · ACM TOSEM 35(2), Article 58, 2026 · 72 页
目前最全的一份 LLM 代码生成综述。给出分类体系与发展脉络，主线的七段是「数据整理 → 数据合成 → 预训练 → 指令微调 → 反馈强化 → 提示工程 → 仓库级与长上下文」；并在 HumanEval、MBPP、BigCodeBench 上把原始论文的结果统一口径做了定量对比，最后专门讨论学术研究与工业落地之间的差距。
Deep learning for code generation: a survey
Zhang 等 · Science China Information Sciences 67(9), 2024
从架构（序贯 / 树 / 图 / 预训练）、模型无关增强策略、评估指标、任务四个视角梳理深度学习代码生成。其中「增强 → 采样 → 重排序 → 修复」这四类不改模型的增益手段单独成章，是我做实验设计时主要参照的部分。

代码编辑

CODIT: Code Editing with Tree-Based Neural Models
Chakraborty 等 · IEEE TSE, 2022
代码编辑方向的经典工作。核心论点：源码词表远大于自然语言，且好的代码变更不能破坏语法结构，所以把 NLP 的神经机器翻译直接搬到代码上是次优的。提出基于树的 NMT 模型来学习代码变更的概率分布，在 2.4 万余个真实变更上训练、5 千个补丁上评估，并能从 Defects4J 的 80 个缺陷里修复 25 个。

软件工程大模型与安全

A survey on large language models for software engineering
Zhang 等 · Science China Information Sciences, 2026
LLM4SE 的全景图：62 个代码大模型、15 类预训练目标、16 类下游任务，覆盖软件工程工作流五个阶段下 112 个具体任务、926 项研究；并单独讨论评测与基准、安全与可靠性、领域微调、压缩与蒸馏。适合用来定位自己的选题落在工作流的哪个阶段。
Security of Language Models for Code: A Systematic Literature Review
Chen 等 · ACM TOSEM, 2026
系统回顾 68 篇，按「攻击 / 防御」两条线组织：后门攻击与后门防御、对抗攻击与对抗防御，并梳理常用模型、数据集、评估指标与开源工具。读完的一个直接结论是——代码模型的安全问题不能照搬 NLP 的那套结论，代码的语法结构与可执行性会带来新的攻击面。

软件维护与变更描述生成

VerLog: Enhancing Release Note Generation for Android Apps using Large Language Models
Guo 等 · ISSTA 2025
用少样本上下文学习激活 LLM 的图推理能力来理解代码变更的语义，再融合细粒度代码修改与高层非代码工件，为 248 个 Android 应用的 42 个版本生成发布说明，在完整性、准确性、可读性上精确率 / 召回率 / F1 最高提升 18%–21%。
SmartNote: An LLM-Powered, Personalised Release Note Generator That Just Works
Daneshyan 等 · FSE 2025
同样做发布说明生成，差异点在个性化：结合项目领域与目标受众做上下文感知，对提交分类并打重要性分数，输出按优先级排列的结构化说明；在完整性、清晰度、简洁性、组织性四项上优于或媲美 DeepRelease 等基线，并明确指出「上下文感知」是效果的主要来源。

这一组和我在做的 HIsCCS 属于同一族问题——让机器自动描述代码变更。HIsCCS 处理变更发生时的提交消息，VerLog 与 SmartNote 处理版本发布时的说明；输入都是代码差异加仓库历史，区别只在粒度与面向的读者。三篇放在一起看，「个性化上下文」这条线是共通的。
